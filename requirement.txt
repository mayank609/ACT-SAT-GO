*REQUIRED* 
Web-based test-taking platform. This is not a basic quiz tool—we need something robust, scalable, and analytics-heavy. Below are the detailed requirements.

 *1. User Roles & Access Control* 
We need a role-based access control (RBAC) system with the following roles:

- *Super Admin* : Full system control
- *Admin/Operations* : Manage users, tests, reports
- *Tutor* : Assigned students + performance analytics access
- *Student* : Test-taking interface only

Permissions should be configurable (not hardcoded), so we can control what each role can view/edit.

 *2. Student & Tutor Management* 

- Ability to create and manage student profiles
- Assign multiple students to a tutor
- Tutors should only see their assigned students
- Bulk upload option (CSV/Excel) for students
- Track student progress over time

 *3. Test Creation Module* 
We need a flexible test builder with:

- Multiple sections (e.g., Math, Reading, Writing)
- Each section should have:
  - Custom time limits
  - Question pools
- Question types:
  - Multiple choice (single correct)
  - Multiple select (multiple correct)
  - Numeric response
- Ability to tag questions by:
  - Topic
  - Difficulty level
  - Sub-topic (for deeper analytics)

 *4. Test Delivery Interface* (Student Side)

- Clean, distraction-free UI
- Section-wise timed tests (auto-submit when time ends)
- Navigation:
  - Question palette (flag, review, unanswered)
- Autosave functionality
- Prevent cheating:
  - Disable tab switching (or track it)
  - Full-screen enforcement (optional)
- Resume capability (in case of disconnection)

 *5. Timer Logic* 

- Each section should have independent timers
- Once a section ends, student moves automatically to next section
- No backward navigation across sections (configurable)

 *6. Analytics & Reporting* (Core Requirement)
This is critical—don’t treat it as a basic score report.

For each student:

- Question-level analytics:
  - Time spent per question
  - Accuracy
- Section-level analytics:
  - Total time vs allocated time
  - Accuracy % per section
- Topic-wise analysis:
  - Performance breakdown by topic/sub-topic
  - Weak vs strong areas

For tutors:

- Dashboard to view all assigned students
- Identify:
  - Time mismanagement patterns
  - Consistently weak topics
  - Improvement trends over time

 *7. Test Attempt Review* 
- Students should be able to review:
  - Correct/incorrect answers
  - Time spent per question
- Tutors should see a more detailed breakdown

 *8. Admin Dashboard* 

- Create/edit/delete tests
- Assign tests to students/groups
- Monitor test attempts in real-time (optional)
- Export reports (PDF/Excel)

 *9. Scalability & Performance* 

- Should handle concurrent test-takers without lag
- Optimized backend for real-time timer sync and autosave
- Preferably built using scalable architecture

 *10. Security* 

- Secure authentication (JWT or OAuth)
- Data protection (student performance data is sensitive)
- Anti-cheating logs (tab switch, inactivity)
